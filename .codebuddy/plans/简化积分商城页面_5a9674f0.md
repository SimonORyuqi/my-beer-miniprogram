## 用户需求

简化积分商城页面，具体需求如下：

1. 积分商品从5个简化为2个：消耗1000积分兑换"330ml升级475ml券"，消耗2000积分兑换"买二送一券"
2. 为每个优惠券商品配置一张展示图片
3. 删除页面中的"面值"、"有效期"、"全场通用"等冗余介绍文字
4. 删除库存数量显示及相关逻辑

## 功能内容

- 积分商城主页展示用户当前积分余额
- 展示2个积分兑换商品卡片，每个卡片包含商品图片、名称、所需积分、兑换按钮
- 点击兑换按钮时检查用户积分是否足够，足够则确认兑换并扣除积分
- 不再展示库存、面值、有效期等信息
- 提供"积分明细"入口按钮

## 视觉效果

- 积分余额以卡片形式展示在页面顶部，使用啤酒金渐变背景
- 商品卡片采用左图右文的横向布局，图片清晰展示优惠券样式
- 兑换按钮根据积分是否足够显示"立即兑换"或"积分不足"状态
- 整体风格与项目现有设计保持一致（主色#D4A017，背景#FFF8F0）

## 技术栈

- 小程序原生开发（WXML + WXSS + JS）
- 本地存储（wx.getStorageSync / wx.setStorageSync）模拟数据
- 预留 CloudBase 后端对接接口

### 数据结构设计

修改后的 pointsProducts 数据格式（简化，去掉 faceValue、validityDays、stock 字段）：

```js
pointsProducts: [
  {
    id: 'p001',
    name: '330ml升级475ml券',
    type: '升级券',
    pointsCost: 1000,
    image: '/images/products/upgrade-coupon.png',
    description: '任意330ml精酿可升级为475ml'
  },
  {
    id: 'p002',
    name: '买二送一券',
    type: '赠送券',
    pointsCost: 2000,
    image: '/images/products/buy2get1-coupon.png',
    description: '购买任意两瓶精酿，赠送同款一瓶'
  }
]
```

### 关键实现细节

1. **mall.wxml 布局调整**：采用左图右文结构，`<image>` 标签展示商品图片，宽度约 200rpx
2. **mall.js 逻辑简化**：删除 `exchangeProduct` 中的库存检查（原第57-64行），删除 `doExchange` 中的库存扣减逻辑（原第96-103行）
3. **图片资源**：将2张优惠券图片置于 `wechat/miniprogram/images/products/` 目录
4. **兑换按钮状态**：仅根据 `userPoints >= item.pointsCost` 判断是否可兑换，移除 `item.stock > 0` 判断

### 性能考虑

- 商品数量固定为2个，列表渲染性能无压力
- 图片使用本地资源，无需网络请求，加载速度快
- 兑换操作仅涉及本地存储读写，无性能瓶颈

## 页面布局设计

### 积分余额卡片（页面顶部）

- 渐变金色背景（#D4A017 → #BF8E14）
- 左侧显示"当前积分"标签
- 中央大字号显示积分数字
- 右侧有"积分明细"入口按钮（带箭头图标）

### 兑换商品列表

- 每个商品卡片采用横向布局（左图右文）
- 左侧：商品图片（200rpx × 200rpx，圆角卡片展示）
- 图片1：330ml升级475ml券（用 upgrade-coupon.png）
- 图片2：买二送一券（用 buy2get1-coupon.png）
- 右侧：商品信息区域
- 商品名称（加粗，30rpx）
- 商品类型标签（小标签，金色边框）
- 商品描述（灰色，24rpx）
- 底部：积分消耗 + 兑换按钮

### 兑换按钮

- 足够积分：金色背景 #D4A017，白色文字"立即兑换"
- 积分不足：灰色背景 #CCCCCC，白色文字"积分不足"
- 点击时有按压缩放效果

## 响应式设计

- 使用 rpx 单位，自动适配不同屏幕尺寸
- 商品卡片内图片和文字区域比例固定（图片占 35%，信息占 65%）
